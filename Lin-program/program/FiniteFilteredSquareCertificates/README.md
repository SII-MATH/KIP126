# Executable certificates for actual filtered quotient squares

The input specifies four finite elementary abelian 2-groups, four complete
filtrations, four matrices `f,p,q,g`, the four leading vectors `x,y,z,w`, and
indices `s,n,m,l`. Each filtration is generated by the complete image of its
matrix at every listed level, with the zero subgroup at all levels at or
above `depth`. Redundant generators are allowed. A shared input fixes every
group and map, avoiding four incompatible copies of a purported square.

`ResultValid D` includes `n <= m+l`, constructs the actual filtered maps,
and concludes

```lean
FilteredExtensionSquare.HasExtension FB FD q
  (D.s+D.n) (D.m+D.l-D.n) D.y D.w
```

Here `HasExtension` is an equation for the constructed quotient differential
on an actual cycle representative with the same leading input. The original
`y` need not itself be a cycle. The groups, filtrations and maps in this
statement are built from the exact matrices in `D`, with no external
interpretation or user-supplied soundness premise.

## Certificate and checks

`Certificate D` contains four complete descent-factor families, four complete
map-preservation factor families, membership witnesses for all four leading
vectors, and an ordinary representative-square certificate. The latter
contains three representative/correction triples, a choice of the first
stability side (`f` or `p`), and a final stability factor.

The checker verifies every listed filtration level, all four leading vector
memberships, the whole matrix equation `q*f=g*p`, all three extension
equations, and the entire higher-source subgroup stability on the selected
first side and final side. It also verifies `n <= m+l`. There is no fourth
extension witness and no stored proposition asserting the desired result.
`check_sound` constructs the four genuine filtered maps, derives the three
actual quotient extension equations and page-defined absence of crossings,
and invokes `FilteredExtensionSquare.square_transfer` for the fourth.

## Wire format and use

Version 1 is strict canonical JSONL with sorted keys, compact JSON, Boolean
bits and row-major matrices. `WireData` fields are `a,b,c,d,ha,hb,hc,hd,depth,
s,n,m,l,f,p,q,g,sourceA,sourceB,sourceC,sourceD,x,y,z,w`. The four source
fields are lists of exactly `depth` generator matrices.

`WireCertificate` fields are `version,data,descentA,descentB,descentC,descentD,
filteredF,filteredP,filteredQ,filteredG,memberX,memberY,memberZ,memberW,
firstRep,firstSource,firstTarget,secondRep,secondSource,secondTarget,
thirdRep,thirdSource,thirdTarget,firstBranch,firstFactor,lastFactor`.
Factor families list exactly `depth` matrices. Factor sizes follow the
generator counts: descents are square, and each map factor has target
generator count rows and source generator count columns. `firstBranch` is
exactly `f` or `p`; its factor has the corresponding dimensions.

The parsers reject empty records, CR, unknown/duplicate fields, unsupported
versions and inconsistent lengths. Diagnostics identify a physical input
line, filtration level and matrix row/column or vector coordinate. Import
elaboration constructs data; it does not supply a trusted proof.

```lean
def wire : WireCertificate :=
  finite_filtered_square_certificate% "FiniteFilteredSquareCertificates/case_nonzero_f.json"

-- The independently defined input fixes every map, vector and index.
theorem requested_result : ResultValid input := by
  finite_filtered_square_cert using certificate
```

`decodeCertificate input wire` decodes only dimensioned witnesses for that
fixed input. Its embedded data cannot change the theorem's input. Wrong
output witnesses are rejected by the checker. `finite_filtered_square_batch%`
imports a JSONL batch; `checkBatch_sound` proves every accepted wire result.
`lin_cert_diagnose using certificate` exposes detailed failures.

## Examples and verification

The four generated fixtures cover both first-stability branches, a nonzero
fourth differential, a fourth raw input `(1,0)` whose sum-map image is outside
the target cycle filtration but whose correction `(1,1)` is a valid cycle,
and depth zero with `s=n=m=l=64`. The two substantive inputs are independently
written in Lean before decoding their witnesses. Examples prove the fixed
results with the tactic and explicitly prove the raw fourth input is not a
cycle. Wrong output, descent and length cases are rejected.

```sh
python3 program/FiniteFilteredSquareCertificates/generate_examples.py
python3 program/FiniteFilteredSquareCertificates/compile.py
python3 program/FiniteFilteredSquareCertificates/review.py
```

All three direct leaves compile with nine standard-or-no-axiom reports.
The compile records bind source, imported JSON, log and object hashes; failed
development logs remain separately recorded and are never counted as proofs.
The semantic replay checks the literal cycle/quotient equation, 125 witness
bit mutations, 94 rejected witnesses and 31 valid alternative witnesses.
The small exhaustive Python fixture generator is untrusted; no C++ output
or hash belongs to the proof trust root. Only standard `propext`,
`Classical.choice` and `Quot.sound` occur in the reported proof dependencies.

These are finite filtered additive-group results. Identifying the groups
with the paper's ESS or homotopy groups, and supplying the synthetic and
classical comparison theorems, remains separate mathematical work.
