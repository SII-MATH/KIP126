# Reference 形式化语义审查报告

本报告针对步骤三的 Lean 文件进行语义审查。审查标准不是“文件能否编译”，
而是：一个 Lean 对象是否真的携带了自然语言数学定义所需要的结构和证明；
一个程序输出是否仍然只是字符串/记录，还是已经被提升为数学命题。

## 结论摘要

目前的代码已经可以作为后续 Lin Program 形式化的类型骨架和语义接口，但不能
声称已经完成 Kervaire 论文的数学形式化或真实程序结果验证。路线图有 229 个
节点，而 Lean 文件约 100 个主要声明；这是因为路线图把每个小概念单独列出，
Lean 则把同一层的公共结构合并成参数化定义。合并只有在下表所列的数学字段
足够强时才是合法的。

| 层 | 当前状态 | 可以直接使用的内容 | 仍需补全的内容 |
|---|---|---|---|
| U/L | 基础定义和内核定理 | F₂、双次数、稀疏向量、有限枚举、线性映射、解析状态、证书容器 | 有限维基、矩阵算法和输入规范化的具体实现 |
| C | 基本定义和定理 | 链/余链复形、循环、边界、同调等价关系及同调商类型、过滤链映射 | 商类型上的群结构、具体链群和同调计算 |
| W | 语义记录接口 | 点空间、连续基点映射、过滤、CW 数据、映射锥/余纤维/稳定谱的命名接口 | 商拓扑构造、CW 附着映射、谱公理和稳定范畴定理 |
| A | 部分结构定义 | Steenrod 词、可容许条件、A-模的次数载体与作用接口 | Adem 右端的有限二项式和、真实 Steenrod 代数及模公理 |
| R | 类型已纠正 | 自由 A-模扩展、分辨率微分类型、增广类型、Hom 循环接口 | 精确性、最小性、Hom 的实际函数空间、Ext 商构造 |

## 已修正的语义问题

1. **同调不再是任意循环代表。** 原先的 `HomologyClass` 只有一个代表元素，
   不能表达“相差边界”的商。现在 `Cycle`、`HomologyEquivalent`、
   `homologySetoid` 和 `Homology` 显式构造了循环元素的边界等价商，并证明了
   自反、对称、传递性。
2. **过滤链映射不再使用无内容的 `Prop`。** `FilteredChainMap.chainMap` 现在
   明确要求逐次数与边界交换，`preservesFiltration` 明确要求保持每一过滤层。
3. **分辨率的微分类型已纠正。** `FreeResolution.differential` 现在是
   第 `s+1` 项到第 `s` 项的 A-模映射，增广是第零项到目标模的 A-模映射，
   并逐次数表达微分平方为零和增广复合为零。
4. **105−101=4 被明确标记为算术事实。** `ExclusionReport` 现在要求保存完整
   候选、排除列表、剩余列表、无重复性、子集关系和分割长度；单独的数字等式
   不能再被误读成已经验证了论文中的 105 行数据。

## 仍然有意保留为接口的字段

`quotientModel`、`structureLaws`、`actionLaws`、`exact`、`minimal`、
`semanticStatement` 等字段目前是有名字的数学命题，而不是自动成立的事实。
它们的作用是强制后续实现者在构造对象时提供相应证明；它们不能由任意字符串
或 C++ 输出自动填充。下一阶段必须把这些接口替换成具体的定义或逐条证明，
尤其是：

- 映射锥、悬挂和稳定谱的商拓扑/谱结构；
- Steenrod Adem 关系及 A-模作用公理；
- 自由分辨率的精确性、最小性和 Ext 商；
- 每条 Lin Program 规则的数学可靠性证明；
- Kervaire 候选表和排除证明树的真实数据。
